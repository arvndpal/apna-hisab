Local data model (SQLite, mirrored in Supabase + RLS user_id = auth.uid())

TableKey fields
transactionsid uuid · type income|expense · amount_paise int · category_id · payment_method cash|upi|card|bank · occurred_at · note · created_at · updated_at · deleted_at · sync_status
categoriesid · type · name · name_hi · icon · is_default · sort · updated_at · deleted_at
udhaar_peopleid · name · phone? · updated_at · deleted_at
udhaar_entriesid · person_id · direction given|received|took|paid · amount_paise · occurred_at · note · updated_at · deleted_at
sync_queueid · table · row_id · op upsert|delete · attempts · last_error · created_at

Money stored as integer paise — no float drift. UUIDs generated on device so offline rows never collide. Udhaar never joins income/expense queries.

Offline-first sync flow

1 · Save → SQLite write + sync_queue row (same transaction). UI updates instantly; toast “Expense added”.
2 · SyncStatus reads pending count from queue → “↻ 2 pending”.
3 · Triggers: app foreground, connectivity regained, after save (debounced 2 s), pull-to-refresh, “Sync now”.
4 · Push: batch upsert to Supabase (≤100 rows). Pull: rows with updated_at > last_pulled_at.
5 · Conflicts: last-write-wins on updated_at; deletes are soft (deleted_at) so they sync too.
6 · Failure: exponential backoff 30 s → 2 m → 10 m; banner “Sync couldn't complete”. Local data is never discarded.

State & forms

Zustand: useAuthStore (session, profile) · useSettingsStore (language, lock, reminder) · useSyncStore (status, pendingCount, lastSyncedAt) · useEntitlementStore (premium). Data lives in SQLite, read via repository hooks (useTransactions(range, filters), useSummary(range)) that re-query on change events. React Hook Form + Zod: amount required, > 0, ≤ ₹1,00,00,000, 2 decimals max; category required; date not in the future beyond today; note ≤ 120 chars. NativeWind classes map 1:1 to the tokens on the design-system board.
